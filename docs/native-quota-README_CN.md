# 原生配额管理与交接指南

本页是中文操作说明。实现约定见 [native-quota-contract.md](native-quota-contract.md)。默认模式为 `off`。此功能不是旧插件的完整等价替代，不执行生产迁移，不自动启用账户，也不自动删除插件或缓存。

## 入口与安全边界

- 浏览器入口：`/native-quota.html`。这是内嵌的无数据静态页面，不需要下载 Management Center，不包含已有密钥、账户或余额。
- 受保护页面：`GET /v0/management/native-quota/ui`。与其他管理 API 一样，需要管理认证请求头。
- 所有数据和操作接口均位于 `/v0/management/native-quota/`，使用现有管理认证、远程管理开关与管理可用性检查。Home 模式不开放这些管理入口。
- `remote-management.disable-control-panel` 同时关闭本页面入口。静态入口只在管理路由已注册且可用时开放。
- 接受 `Authorization: Bearer <management-key>` 或 `X-Management-Key: <management-key>`。密钥不得放入查询参数、分享链接、终端历史或日志。
- 页面密钥只驻留在当前页面内存；连接后清空密码输入框；清除、刷新或离开页面后需重新输入。不使用 cookie、浏览器持久化存储、外部脚本、字体或图片。
- 页面仅向同源固定管理路径发出请求，不跟随重定向。HTML 使用内容安全策略哈希；动态文字通过 DOM `textContent` 写入，不作为 HTML 解析。
- 使用可信 HTTPS 或本机连接。此页面不是防止恶意浏览器扩展读取页面内存的安全隔离区。

页面以紧凑表格展示凭据 ID、提供方、模式、状态与原因、观测年龄、有效期、配额池和模型、窗口、剩余比例、重置时间、在途数量及权重。配额 `remaining` 是原始比例，不是取整百分比；`null` 与空观测显示为未知。未来重置时间只是上游证据，不承诺届时一定恢复。

“读取状态”只读取本地快照。“查询上游配额”按单个已存在的凭据 ID 入队，由采集器合并或限流。自动读取状态默认关闭；用户勾选后每 30 秒执行一次，仅在页面可见时运行。自动读取不会覆盖配置编辑框中的未保存修改。

## 完整配置

配置文件中的示例（仅说明，不会自动写入环境）：

```yaml
native-quota:
  mode: off
  providers: [antigravity, codex]
  refresh-concurrency: 2
  antigravity-interval: 5m
  codex-interval: 15m
  refresh-min-interval: 30s
  max-wait: 2s
  max-in-flight: 4
  unknown-max-in-flight: 1
  queue-limit: 64
```

- `off`：不主动查询配额，不参与路由或准入。
- `shadow`：可进行受限的配额观测，但不以配额状态改变路由、准入或手动禁用/优先级。
- `enforce`：启用已实现的配额准入与路由决策；要求旧调度器完成明确交接，拒绝 Home 或旧调度器配置/运行态冲突。
- `max-wait` 限制累计排队等待，最大 `2s`，不是已建立的生成请求或流的超时。
- 提供方只接受 `antigravity` / `codex`；空数组表示不覆盖任何提供方。重复项和未知提供方不接受。
- PUT 必须包含全部 10 个字段，字段名使用上述连字符格式。空模式、空时长、零/负限制、未知字段、重复 JSON 键和尾随 JSON 均拒绝。时长必须可解析且为正，最终范围由共享配置验证器检查。
- 状态接口把配置文件中隐含的默认值展开为可提交的完整对象；此展开不会写文件。`config.mode` 与 `runtime_mode` 分开展示，便于发现配置/运行态差异。

## 额度状态持久化

服务以配置路径与 auth-dir 生成实例专属状态目录：配置文件同级的 `.native-quota-state/<实例摘要>/snapshot.json`。它在凭据目录之外，不会被 auth watcher 当作凭据导入。

- `off` 不启动保存任务、不创建状态目录。匿名嵌入式服务（没有配置路径或 auth-dir）不自动保存。
- `shadow/enforce` 启动时校验并恢复有效快照；只匹配当前账号与稳定身份版本，旧证据不能覆盖更新观测。
- 每分钟检查一次，快照未变化不重复落盘；正常停机在关闭额度服务前保存一次。
- 快照只包含额度/健康证据、观测时间和身份摘要，不包含 OAuth token、人工优先级、disabled、在途任务或队列。
- 损坏文件不被当作健康余额；保留原生安全限制，并重新查询。保存不可用会告警，不代表持久化已完成。
- 保存测试覆盖临时文件同步与替换、尾量精度、off无副作用及停机恢复；不保证断电时最后一分钟观测不丢失。

## 管理 API

所有以下路径均以 `/v0/management/native-quota` 为前缀，必须使用管理认证请求头。响应禁止缓存。请求体上限 64 KiB；错误响应不会回显请求体、令牌或上游响应。

| 方法与路径 | 输入 | 结果与边界 |
| --- | --- | --- |
| `GET /status` | `page` 默认 1，最大 1000000；`page_size` 默认 50，范围 1–200；可选 `provider`、`state`、`auth_id` 精确过滤 | 返回 `config`、`runtime_mode`、`accounts`、`events`、`total`、`has_more`、分页与 `server_time`；账户按 ID 排序。事件只包含当前页凭据，最多 100 条。不返回 auth metadata 或密钥。 |
| `POST /refresh` | `{"auth_id":"已有精确ID"}` | 返回 202 和 `queued`；false 表示可能已合并/受限，不表示新的上游查询完成。不存在 ID 返回 404；不将 ID 解释为 URL、文件名或 auth index。off、手动禁用、API-key 类型或未覆盖提供方不会查询。 |
| `PUT /config` | 完整原生配额对象，不带 `native-quota` 外层 | 类型/结构错误 400，值不合法 422，交接冲突 409；成功 200。只替换原生配额配置，保留其他运行配置，通过既有 reload snapshot 路径发布。 |
| `POST /migration/preview` | 下文的版本化用户输入与显式映射 | 只读；返回 `dry_run:true`、`execution_allowed:false`。没有迁移执行接口。 |
| `POST /plugins/stop` | `{"id":"antigravity-priority"}` 或 `{"id":"codex-quota-scheduler"}` | 显式的插件生命周期操作，不是迁移。要求对应插件配置明确 `enabled:false`，等待 Host 确认关闭；不改配置、不删除二进制/缓存、不启用账户。取消/未确认返回 409 和 `stopped:false`，不能当作已停止。 |
| `GET /ui` | 无 | 返回同一内嵌无数据 HTML。浏览器直接打开请优先使用静态入口并填写密钥。 |

状态中的 `age_seconds` 在没有观测时为 `null`；有效期和重置时间采用 RFC 3339 时间。引擎的零时间在 UI 显示为未知。`weight` 是引擎决策权重，不是配额余额，也不写入凭据优先级。账户级状态是摘要；仍应检查各配额池、窗口和模型范围，不把一个池的阻塞推广到所有模型。

### 保存与失败处理

新配置先完整验证，包括旧调度器配置与运行态所有权检查，再克隆完整配置。管理端在同目录私有临时文件中调用现有的保留注释序列化器，完成同步后替换配置文件；应用失败时恢复原始文件字节，成功后发布管理快照并调用既有 reload 路径。普通文件以外的目标（包括符号链接）拒绝此保存路径。

`config_save_failed` 表示没有提交新配置；`config_apply_failed` 表示应用失败并已恢复原始文件。`config_changed_retry` 表示准备阶段发现配置文件被其他写入者改变，应重新读取后再操作。`config_rollback_failed` 表示恢复未确认，`previous_state_preserved:false`，必须立即停止继续切换并人工核对。

临时替换和回滚已由隔离 Windows 文件测试覆盖；这不是断电持久性或所有文件系统原子性保证。不要同时使用外部编辑器、通用配置接口和此配置入口修改同一配置；既有文件 watcher/reload 回调并非跨进程事务。旧 reload 回调没有错误返回接口，因此跨系统交接仍需以下验收与回滚检查。

## 只读迁移预览

固定来源白名单：

| 插件 ID | 允许的声明版本 | 提供方 |
| --- | --- | --- |
| `antigravity-priority` | `1.2.20` | `antigravity` |
| `codex-quota-scheduler` | `0.2.1` | `codex` |

这些是已审阅来源版本标识，**不是自动探测或证明当前正在运行的版本**。预览响应明确标记 `source_verification:user_supplied_version_not_live_verified`。未知来源、版本、额外配置字段拒绝；后续新增版本须单独审阅，不能只修改请求中的版本绕过。

请求示例：

```json
{
  "schema_version": 1,
  "plugin_id": "antigravity-priority",
  "plugin_version": "1.2.20",
  "user_config": {"refresh_interval": "5m"},
  "credential_mappings": [
    {"credential_id": "operator-verified-old-id", "auth_id": "existing-cpa-auth-id"}
  ]
}
```

唯一允许迁入提案的用户配置字段是 `refresh_interval`，映射到相应提供方的刷新间隔。凭据映射必须由操作者显式提供，1–200 条，一一对应，目标必须真实存在且提供方匹配。`credential_id` 是操作者核实的旧标识，**不是凭据内容**；服务端不读取旧缓存、任意路径、远程 URL 或凭据文件进行推断。

结果列出当前 disabled、当前优先级和保留提案，给出 `shadow` 模式候选配置。它不复制插件运行状态，也不改写任何配置或凭据。

- 明确手动禁用的账户保持禁用。
- 无法判定禁用来源时也保持禁用，等待人工取证。
- **96–100 的优先级不能证明由插件设置**；没有明确所有权证据就保留原值。
- 缺失插件状态不是批量启用账户或重置优先级的理由。
- 预览完成不代表允许 enforce，更不代表已经迁移。

## 交接操作规程（人工批准后，仅先在隔离环境验证）

1. 记录 CPA 版本、原生配额完整配置、路由配置、实际加载的插件 ID/版本、旧插件配置与缓存，以及凭据 ID/disabled/优先级的已确认来源。妥善备份，限制访问；不要把令牌放入工单、截图或日志。
2. 保持 `off`，执行只读预览。逐项核实 ID 映射、配额池/模型范围、手动禁用和优先级。预览不提供实际插件版本验证，也不自动恢复插件字段。
3. 在隔离环境按批准配置运行 `shadow`。验证真实观测、零余额、低比例、未知数据、过期、重置时间、单池 429、限流合并，以及稳定的手动禁用。比较生成流量路由与未启用原生配额时是否一致。
4. **明确修改对应旧插件的 `enabled:false` 并等待配置 reload。** 全局 `plugins.enabled:false`、插件从菜单消失或配置缺失，都不等价于插件后台循环已退出。
5. 对两个白名单插件分别显式调用 `POST /plugins/stop`。只有返回 `stopped:true` 才代表此次 Host 关闭确认；取消、超时或 409 均不能当作成功，旧运行态仍可能构成冲突。该接口不会删除文件/缓存，也不会自动完成第 4 步。
6. 等待旧插件已接纳的 auth 写入排空；核对其不会再改写 disabled/priority。若手动标记来源仍不清楚，停止交接，不做“清理”推断。
7. 通过完整配置 PUT 显式选择 `enforce`。出现 409 不要绕过验证，不要自动重新启用旧插件。核对配置模式、运行模式、实际生成路径、并发准入、队列取消、流终止释放与低优先级回退。
8. 验收通过前，不宣布与旧插件全部功能等价，不执行生产变更。本开发任务没有读取生产凭据、调用生产配额或执行部署。

## 回滚规程

1. 暂停所有配置写入和交接操作。保存安全的错误码与时间，勿记录密钥或 auth 内容。
2. 提交完整 `off` 配置，确认 PUT 成功并核对 `config.mode` / `runtime_mode`。如果保存/应用/回滚不确认，停止操作，由维护者核实磁盘配置与实际运行模式；不要在可能仍为 enforce 时重启旧调度器。
3. 保留原生配额状态用于诊断；不把诊断快照作为新的真实余额。回滚不需要删除 auth 文件、刷新令牌或重置账户。
4. 只有确认原生策略退出后，才按已批准的原始配置恢复旧插件。使用其既有生命周期启动路径，核对实际加载版本与回调；停止接口不会替你重新启动插件。
5. 凭据 disabled 和优先级仅按逐项记录的明确来源恢复。没有证据的标记保持原状；禁止按 96–100 区间批量恢复/启用。
6. 检查重启后的配置、提供方范围与生成/流生命周期；发现双重调度立即停止切换。保留受控备份，直到后续验收完成。

## AG / Codex 功能对照与未交付项

“当前”表示本分支的原生能力，不表示任何生产部署或旧插件全功能等价。管理层不替代引擎/认证层的跨路径验收。

| 能力 | Antigravity 当前 | Codex 当前 | 范围 / 后续 |
| --- | --- | --- | --- |
| 本地状态、分页/过滤、原因/年龄/重置/在途/权重 | 已实现 | 已实现 | 只展示引擎证据，不伪造余额 |
| 固定端点采集、单 ID 异步刷新 | 由原生采集器及现有受管执行器实现 | 同左 | 不提供任意 URL 测试器，不重复实现 OAuth |
| 多配额池/窗口与模型关联 | `gemini`、`claude_gpt` 及窗口证据 | `codex` 与具体限制池/窗口 | 未知模型/缺失关联保持保守；不是任意未来提供方兼容保证 |
| off / shadow / enforce 与准入 | 有原生实现，须通过引擎/认证验收 | 同左 | 不改写 auth 优先级实现权重；保留手动禁用 |
| 重置时刻驱动观测 | 展示及使用上游重置证据 | 同左 | 不等于发送激活生成请求，也不保证供应商重置准时 |
| 旧调度器运行态交接 | 明确禁用后显式 stop | 同左 | 不自动停插件；未确认关闭时拒绝 enforce |
| 内嵌轻量操作 UI | 已实现 | 已实现 | 无框架、无外部资源；不是下载式 Management Center 的源码改造 |
| 迁移字段和凭据 ID 预览 | 固定来源/版本，只读 | 同左 | 仅 `refresh_interval`；无旧缓存/账户状态自动导入 |
| 自动执行迁移 / 自动恢复 disabled、priority | **未提供** | **未提供** | 需额外取证、设计和验收；不是本任务交付 |
| 旧插件的可选主动激活、周期探测生成、付费额度/模型回退 | **不宣称支持** | **不宣称支持** | 没有相应实现时保留为未迁移功能，不能假称对等 |
| 历史趋势、持久事件仓库、完整迁移向导 | **未提供** | **未提供** | 事件仅有限内存窗口，页面不是审计存储 |

## 隔离验证

- Go httptest 使用现有管理认证，覆盖所有变更接口的两种有效请求头、无认证/查询参数密钥拒绝、精确 ID、URL 注入拒绝、完整配置校验、冲突、保存失败和应用失败回滚。
- 静态 HTML 解析测试检查无外部资源、无内联事件、CSP、密码输入、可访问表格及默认关闭自动刷新。
- `native_quota_assets/native_quota_dom_test.cjs` 使用 Node 内置测试运行器与最小 DOM，不启动浏览器、不安装依赖、不连接网络；覆盖 XSS 文本、精度、固定认证路径、可见性轮询、未保存配置和清除后的迟到响应。
- 引擎、认证集成与插件生命周期验收由各自测试覆盖。测试通过不等于进行过生产流量或凭据验证。
